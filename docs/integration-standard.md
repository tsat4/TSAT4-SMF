# มาตรฐานร่วม 2 โปรเจกต์ (Render + Supabase)

ร่าง 2026-10-30 · ใช้กับ: TSAT4 SMF (tsat4-smf.onrender.com) และโปรเจกต์ของเพื่อน · ทั้งสองฝั่งตกลงใช้มาตรฐานนี้ร่วมกัน
หลัก: **ต่างคนต่างมี Render + Supabase ของตัวเอง** แลกกันแค่ข้อมูล · หัวข้อ "ต้องเหมือนกัน" ห้ามต่างกัน · หัวข้อ "เลือกเองได้" แต่ละฝั่งทำตามถนัด

## 1. เทคโนโลยี

| ส่วน | TSAT4 SMF ใช้ | มาตรฐานร่วม |
|---|---|---|
| Hosting | Render (Web Service, Node) | **ต้องเหมือนกัน**: Render แยกบัญชี / service ของใครของมัน |
| ฐานข้อมูล | Supabase (Postgres) 2 โปรเจกต์ | **ต้องเหมือนกัน**: Supabase ของใครของมัน |
| เซิร์ฟเวอร์ | Node.js 22 + Express 4 · JavaScript (ES modules) | แนะนำ Node.js ≥ 20 · ภาษา / framework เลือกเองได้ |
| เชื่อม Supabase | `@supabase/supabase-js` v2 ฝั่งเซิร์ฟเวอร์เท่านั้น (service key อยู่บน Render) | **ต้องเหมือนกัน**: เบราว์เซอร์ไม่ถือคีย์ฐานข้อมูล ทุกอย่างผ่านเซิร์ฟเวอร์ |
| หน้าเว็บ | HTML + CSS + JavaScript ธรรมดา (ไม่มี React / Next.js / TypeScript) | เลือกเองได้ (React, Next.js, Vue หรือแบบเรา) ไม่กระทบการแลกข้อมูล |
| Deploy | push ขึ้น GitHub branch `main` → Render deploy อัตโนมัติ | แนะนำแบบเดียวกัน |

## 2. การแลกข้อมูล

- **อ่านอย่างเดียว ผ่าน view แชร์**: ฝั่งเจ้าของข้อมูลสร้าง view ชื่อ `share_<ข้อมูล>` (เช่น `share_employee`) เลือกเฉพาะคอลัมน์ที่ให้ได้
- อีกฝั่งอ่านด้วย `supabase-js` (URL ของเจ้าของ + **คีย์อ่านอย่างเดียวเฉพาะคู่นี้**) จากเซิร์ฟเวอร์ของตัวเอง
- ห้ามเขียนลงฐานของอีกฝั่ง · ถ้าอีกฝั่งต้องการข้อมูลจากเรา ให้เขาเปิด view แชร์ของเขาให้เราดึงเหมือนกัน
- ต้องส่งเข้าไปบันทึกทันที (ไม่ใช่แค่อ่าน): ใช้ API ของ Render อีกฝั่ง `POST /api/integration/v1/...` + header `X-Api-Key` (ตกลงกันเป็นกรณี)
- เปลี่ยนรูปแบบ view: สร้าง `share_<ข้อมูล>_v2` คู่ไว้ก่อน ห้ามแก้ของเดิมจนอีกฝั่งย้ายเสร็จ

## 3. รูปแบบข้อมูล (ต้องเหมือนกัน)

| เรื่อง | มาตรฐาน | ตัวอย่าง |
|---|---|---|
| ชื่อตาราง | `mt_<ระบบ>_<ชื่อ>` ข้อมูลหลัก · `tx_<ระบบ>_<ชื่อ>` รายการ · `share_` สำหรับแชร์ | `mt_main_employee`, `share_employee` |
| ชื่อคอลัมน์ | snake_case อังกฤษ | `employee_id`, `cost_center` |
| รหัสผูกข้อมูล | ใช้รหัสธุรกิจ ไม่ใช้ id ภายใน | `employee_id` (รหัสพนักงาน), `costcenter` |
| วันที่ | `YYYY-MM-DD` | `2026-10-30` |
| วันเวลา | ISO 8601 UTC (`timestamptz`) | `2026-10-30T07:15:00Z` |
| ตัวเลข / เงิน | number ไม่มีคอมมา · ทศนิยมด้วยจุด | `1234.5` |
| สถานะเอกสาร | ตัวพิมพ์ใหญ่ | `DRAFT`, `SUBMITTED`, `APPROVED`, `REJECTED` |
| สถานะข้อมูลหลัก | `Active` / `Inactive` | |
| ข้อความ | UTF-8 (ภาษาไทยได้) · ตัดช่องว่างหัวท้าย | |

## 4. เจ้าของข้อมูล (แก้ได้ที่เจ้าของเท่านั้น)

| ข้อมูล | เจ้าของ | อีกฝั่ง |
|---|---|---|
| พนักงาน (`employee_id`, ชื่อ, หน่วยงาน, ระดับ) | TSAT4 SMF (`mt_main_employee`) | อ่านจาก `share_employee` |
| Cost center / หน่วยงาน | TSAT4 SMF (`mt_main_costcenter`) | อ่านจาก `share_costcenter` |
| (เพิ่มตามที่ตกลง) | | |

## 5. ความปลอดภัย

- คีย์ทุกตัว (Supabase service key, คีย์อ่านอย่างเดียว, API key) เก็บใน **Environment ของ Render** เท่านั้น · ห้ามใส่ใน git / แชท / หน้าเว็บ
- คีย์อ่านอย่างเดียวของอีกฝั่ง = Postgres role ที่ `select` ได้เฉพาะ view `share_*` · ห้ามให้ service key กัน
- เปิด RLS ทุกตารางจริง

## 6. Render แผนฟรี

- เครื่องหลับเมื่อไม่มีคนใช้ เรียกครั้งแรกอาจช้า ~1 นาที · ฝั่งที่ดึงข้อมูลตั้ง timeout ≥ 60 วินาที และลองใหม่ 2–3 ครั้ง
- ทั้งสองฝั่งมี `GET /api/health` ตอบ `{ "ok": true }`

## 7. เมื่อจะเปลี่ยนสิ่งที่แชร์

แก้เอกสารนี้ (ทั้งสองฝั่งถือฉบับเดียวกัน) → แจ้งอีกฝั่ง → ค่อยแก้ view / API
