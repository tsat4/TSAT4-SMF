# รวมฐาน TX เข้า MX และตัดสต็อกแบบ atomic

**เป้าหมาย:** ย้ายตาราง `tx_*` ทั้งหมดจากโปรเจกต์ TX (`loeyrgavlpdnrbczjxpl`) ไปไว้ใน MX (`ezhyitqznflvjnwuuchn`)
เพื่อให้ใบเบิกกับสต็อกอยู่ฐานเดียวกัน แล้วการรับของจะตัดสต็อกได้ใน transaction เดียว

**ไม่ต้องแก้โค้ด** server ใช้ client `tx` ตาม env `TX_*` ถ้าเปลี่ยน env ให้ชี้ไป MX ก็ใช้ฐานเดียวกันทันที
ส่วน `tx_sto_receive` server จะใช้เองเมื่อฟังก์ชันนี้มีอยู่ ถ้ายังไม่มีก็ใช้วิธีเดิม

| ขั้น | ใครทำ | ทำอะไร | กระทบระบบ live |
|---|---|---|---|
| 1 | ผู้ใช้ | รัน `01_inspect.sql` ใน SQL Editor ของ **TX** และ **MX** แล้ว copy ผลทั้งช่องส่งให้ AI | ไม่กระทบ (อ่านอย่างเดียว) |
| 2 | AI เขียน → ผู้ใช้รัน | AI เขียน `02_create_tx_in_mx.sql` จากผลขั้นที่ 1 แล้วผู้ใช้รันใน **MX** (สร้างตารางเปล่า ยังไม่มี trigger) | ไม่กระทบ (ยังไม่มีใครใช้ตารางใหม่) |
| 3 | ผู้ใช้ | ใส่ key ทั้ง 4 ตัวใน `.env` (ดู `.env.example`) แล้วรัน `npm run migrate:tx -- --dry` ตามด้วย `npm run migrate:tx` | ไม่กระทบ (อ่าน TX แล้วเขียน MX) |
| 4 | ผู้ใช้ | รัน `03_receive_rpc.sql` ใน **MX** และรันส่วน trigger/function ท้ายไฟล์ 02 (ถ้ามี) | ไม่กระทบ |
| 5 | ผู้ใช้ | **ช่วงที่ไม่มีคนใช้งาน:** รัน `npm run migrate:tx` อีกครั้ง (ดึงรายการล่าสุด) แล้วเปลี่ยน env บน Render: `TX_SUPABASE_URL` = ค่าเดียวกับ `MX_SUPABASE_URL` และ `TX_SUPABASE_SECRET_KEY` = ค่าเดียวกับ `MX_SUPABASE_SECRET_KEY` | Render restart ประมาณ 1 นาที |
| 6 | ผู้ใช้ + AI | ทดสอบ: login, เบิก, จัด, จ่าย, รับของ แล้วดูว่ายอด Current ลดลง | — |

**ย้อนกลับ:** คืนค่า env `TX_*` บน Render เป็นค่าเดิม ระบบจะกลับไปใช้ฐาน TX ทันที (ใบเบิกที่สร้างหลังขั้นที่ 5 จะอยู่ใน MX เท่านั้น)
**อย่าลบโปรเจกต์ TX** จนกว่าจะใช้งานฐานรวมได้ราบรื่นอย่างน้อย 2 สัปดาห์

หมายเหตุสำหรับ AI ที่เขียนไฟล์ 02:
- เปลี่ยน `generated always as identity` เป็น `generated by default as identity` ทุกจุด ไม่อย่างนั้นจะคัดลอก id เดิมไม่ได้
- trigger และ function ของ TX ให้แยกไว้ท้ายไฟล์ แล้วรันหลังคัดลอกข้อมูลเสร็จ เพื่อไม่ให้ trigger ทำงานซ้ำตอนคัดลอก
- ตรวจ signature ของ `mt_sto_stock_adjust` จากผล inspect ของ MX ให้ตรงกับที่ `03_receive_rpc.sql` เรียกใช้
- เปิด RLS ตามต้นฉบับ (server ใช้ service key ซึ่งข้าม RLS อยู่แล้ว)
